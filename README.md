# 카페 레시피 연습

랜덤으로 들어오는 주문(1~4잔)을 보고, 잔마다 **재료의 위치·종류·양**과 **포장**을 입력해 채점받는 레시피 암기 도구입니다. 일하면서 폰으로 쓰는 걸 전제로 모바일 우선으로 만들었습니다.

## 데이터를 레포에 두지 않는 구조

실제 레시피는 사내 자료라 공개 저장소에 올릴 수 없습니다. 그래서 코드와 데이터를 분리했습니다.

- 앱은 GitHub Pages에 공개 배포되는 정적 사이트이고, 레시피는 포함되어 있지 않습니다.
- 사용자가 JSON 파일을 직접 올리면 브라우저에서만 읽고, 이 기기의 브라우저 저장소(localStorage)에만 보관합니다. 서버로 전송되는 데이터는 없습니다.
- `.gitignore`로 `*.xlsx`, `recipes.json`을 막아 실수로 커밋되지 않게 했습니다.
- 처음 보는 사람도 체험할 수 있도록 가상 메뉴로 만든 `public/demo.json`을 넣었습니다.

## 데이터 파이프라인

```
레시피 xlsx (편집용 원본)  →  scripts/xlsx_to_json.py  →  recipes.json  →  앱에 업로드
```

메뉴 추가나 단종 반영은 엑셀에서 하고, 스크립트로 변환합니다. 변환 단계에서 채점 규칙을 데이터에 미리 반영해 두기 때문에 앱은 판단 로직 없이 읽기만 합니다.

| 필드 | 의미 |
| --- | --- |
| `gradeSizes` | 이 재료를 채점하는 사이즈 (예: 디스펜서로 자동 계량되는 사이즈는 제외) |
| `presenceOnly` | 양은 보지 않고 넣었는지만 확인 (블렌딩이 아닌 음료의 얼음 등) |
| `gradeLocation` | 재료 위치를 채점할지 여부 (얼음, 시럽 펌프처럼 눈에 잘 띄는 재료는 제외) |
| `T/t` 단위 | `"3T 1t"` → `{"T":3,"t":1}`로 쪼개서 큰술·작은술 입력칸과 비교 |

```bash
pip install openpyxl
python scripts/xlsx_to_json.py 레시피.xlsx recipes.json
```

## 채점 규칙

- 재료 순서는 보지 않고, 양은 정확히 일치해야 정답
- 같은 재료가 두 번 들어가는 레시피(얼음①②)는 양이 맞는 입력부터 짝지어 채점
- 틀린 이유를 빠짐 / 불필요 / 위치 틀림 / 양 틀림으로 구분
- 포장: 잔 단위(빨대 등)와 주문 단위(캐리어, 봉투 등)를 따로 채점, 매장 내 취식은 채점 안 함

## 실행

```bash
npm install
npm run dev
```

`main` 브랜치에 push하면 `.github/workflows/deploy.yml`이 빌드해서 GitHub Pages에 배포합니다. 저장소 Settings → Pages에서 Source를 **GitHub Actions**로 설정해 두세요.
